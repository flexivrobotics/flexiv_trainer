End-effector control · software + hardware

From one bit to a dexterous hand.

The current trigger path is binary: a physical input becomes True or False, then selects open or close. A multi-joint hand needs timestamped numeric vectors, a bidirectional transport, and a dedicated device service.

Direct answer Important

Digital I/O does not carry a continuous joint signal.

In this repository the selected input is explicitly converted to a Boolean before the gripper command is chosen.

02 · Signal semantics

Why DI cannot represent hand pose

“Digital I/O” means discrete logic levels. It is not the same as a digital communications bus that serializes structured packets.

1 0

An intermediate or out-of-spec voltage is invalid/undefined input—not a fractional data value.

Not a data bus

No state exists between open and close.

Width, velocity, and force come from configuration after the Boolean decision; the button does not encode them.

  • No per-joint position or velocity vector
  • No timestamp or sequence number
  • No packet integrity or practical feedback channel

03 · USB-C camera analogy

Borrow the architecture, not the image format

The camera code is a strong model for exclusive device ownership and continuous acquisition. A hand also needs a validated reverse command path.

How RGB arrives in this repository

continuous stream → latest-frame cache
01 · DEVICE

USB camera

RealSense or Orbbec is discovered by serial and opened through its vendor SDK.

02 · BACKEND

Decode

pyrealsense2 / pyorbbecsdk returns color and optional depth arrays.

03 · OWNER THREAD

Acquire

One thread calls stream.read(), timestamps data, tracks health, and restarts silent devices.

04 · CACHE

Share latest

Preview, recording, and rollout consume cached NumPy payloads without racing the device.

Reuse for a hand

  • Backend abstraction: discover/open/read/stop
  • One owning I/O thread per device
  • Timestamped latest-state cache
  • Health, timeout, and reconnect reporting

Do not reuse literally

  • RGB arrays or PNG encoding
  • UVC as a joint-control protocol
  • One-way acquisition assumptions
  • Newest-wins without command-age safety
USB-C
USB-C is a connector, not the application protocol.
Identify what the exact hand exposes: vendor SDK, USB CDC serial, bulk endpoints, USB Ethernet, CAN adapter, or another bus. UVC is for video-class devices, not general motor control.

04 · Recommended target

Bidirectional dex-hand pipeline

Keep DI only as an optional enable or mode signal. Put joint commands and feedback on the hand’s supported packet transport.

05 · Repository plan

How to add the hand cleanly

The required first input is the exact hand model and communication manual: joint count, command modes, rate, calibration, and fail-safe behavior.

Four incremental slices

separable and testable
01 · CONTRACT

Model the device

Typed configuration, joint names and limits, command rate, timeout, DexHandCommand, and DexHandState.

02 · BACKEND

Isolate vendor I/O

Define discover/open/read_state/write_command/stop. Keep packets out of teleop and rollout.

03 · SERVICE

Own the I/O loop

Dedicated thread, latest command/state, health, timeout, reconnect policy, and exclusive ownership.

04 · INTEGRATE

Record + control

Add API/UI status, measured q/dq recording, teleop source, and a latest-only rollout executor.

Independent stopPreserve the robot/hand hardware stop chain.
Stale commandStop or hold according to validated vendor guidance.
